## Loading them

`src/lib/constants/assets.ts` exposes `asset(key)` plus `BRAND` and `TRUCK_MARKER`.
Nothing is imported at build time, so the bundle does not grow:

```svelte
import { asset, BRAND } from '$lib/constants/assets';
<img src={BRAND.logoSidebar} alt="Karlo" />
<img src={asset('icon/legend-planner/truckIdle.png')} alt="" />
```

`PUBLIC_ASSET_BASE_URL` overrides the host for CloudFront or a staging bucket.

The bucket serves these publicly through a policy scoped to `assets/*`:
`s3:GetObject` for `*` on that prefix only — no listing, no writes, and anything
outside `assets/` stays private. ACLs are disabled on the bucket
(`BucketOwnerEnforced`), so the policy is the only grant.

Live in the app: the topbar wordmark (`img/LogoKarlo.png`, exactly the 79x23 the
spec calls for), the planner's truck pins, and the planner legend swatches.
Verified loading with 200s and no broken images.

Note the two truck icon sets are different artwork, not duplicates —
`icon/truck*.png` is an 18x81 map pin, `icon/legend-planner/truck*.png` an 81x18
legend swatch. An earlier flattened key scheme collided them; keys now mirror
the full source path.

`static/` holds only `favicon.svg` now — browsers request it before any app code
runs, so it stays local.
